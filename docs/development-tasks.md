## 4. 跨阶段关注点

以下关注点贯穿所有阶段，需在对应阶段持续落实：

- **OpenAPI 契约**：后端维护 Schema/枚举/示例/错误码；前端生成 TS 类型，不另建冲突 DTO。不兼容变更先更新和评审契约。
- **权限隔离**：所有资源通过 `FamilyScope` 隔离，跨家庭和跨猫访问测试通过。前端按权限展示并处理 401/403。
- **时间/单位**：后端返回 UTC/RFC 3339 与家庭时区；前端转为家庭时区展示和录入。
- **幂等**：写接口接收 `Idempotency-Key`，响应附带 `request_id`。前端每次逻辑操作生成并复用同一键。
- **AI 安全**：AI 草稿/病历/摘要/问答均有状态、版本、证据及降级路径。前端显式呈现、编辑、确认前不当正式记录。
- **日志脱敏**：日志不记录密码、Token、AI Key、完整病历、完整 Prompt/响应或文件正文。
- **测试**：后端单元/集成/契约/故障测试；前端单元/组件/E2E/视觉验收。

## 5. 前后端联调约定

接口开发顺序为"OpenAPI 与示例 → 后端实现与契约测试 → 前端取消 Mock 联调"。

| 契约项 | 后端责任 | 前端责任 |
|---|---|---|
| OpenAPI | 维护 Schema、枚举、示例和错误码 | 生成 TS 类型，不另建冲突 DTO |
| 权限 | 最终校验并返回权限集 | 按权限展示并处理 401/403 |
| 时间 | 返回 UTC/RFC 3339 与家庭时区 | 转为家庭时区展示和录入 |
| 幂等 | 保存并复用逻辑操作结果 | 同一重试复用同一 Key |
| AI | 状态机、Schema、证据和安全边界 | 草稿编辑、确认和依据展示 |
| 趋势 | 数值、单位和缺失标记 | 不改变语义地可视化 |
| 上传 | 安全校验、状态、权限下载 | 进度、取消、重试和预览 |
| 错误 | 稳定 code、message、request_id | 分级反馈并展示请求 ID |

## 6. 质量门禁与完成定义

每阶段交付实现代码、migration、OpenAPI、测试、配置样例、变更清单、验证命令、已知风险和下一阶段计划。

**后端合并前执行：** `gofmt`、`go vet`、约定静态检查、单元/集成/契约测试、`go build`、OpenAPI 校验、空库 migration、关键回滚验证及敏感日志检查。

**前端合并前执行：** 依赖锁检查、`vue-tsc`、ESLint、Prettier、Vitest、关键 Playwright 用例、生产构建及 OpenAPI 生成代码差异检查。

## 7. 开发顺序建议

1. **B1/F1 → B2/F2**：先完成设计和基础工程，为后续阶段提供契约和框架。
2. **B3 → B4 → B5**：按数据依赖顺序推进（家庭/猫咪 → 记录/时间线 → 提醒/用药/库存）。
3. **B6 → B7 → B8**：AI/医疗/时光/导出依次推进，每阶段依赖前一阶段的数据能力。
4. **B9**：整体验收，补齐测试、安全和文档。

前端各阶段可在后端对应阶段完成 OpenAPI 契约后并行开发，通过 Mock 数据推进，联调时替换为真实 API。
