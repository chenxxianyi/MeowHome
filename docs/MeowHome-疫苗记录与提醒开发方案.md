# MeowHome 疫苗记录与日期待办开发方案

> 文档版本：v1.1  
> 编制日期：2026-10-22  
> 文档状态：开发方案  
> 关联模块：小程序快速记录、猫咪档案、提醒中心、猫管家 Agent、后端记录与提醒服务
> 本次修订：补充记录页日历浏览、日期口径、查询设计和验收标准。

## 1. 目标

用户记录猫咪完成一次疫苗接种后，系统根据疫苗类型、猫咪年龄、针次和接种史，给出可解释的下一次接种时间建议。用户核对或调整日期后，可创建疫苗待办，并在提醒中心查看和完成。

功能需要形成以下闭环：

```text
填写接种记录
    → 生成有依据的下一针建议
    → 用户核对并确认提醒日期
    → 提醒中心显示日期待办
    → 完成接种后关联新记录并进入下一针判断
```

系统提供接种记录管理和时间提醒，不替代兽医制定个体接种方案。没有足够信息时，提示用户补录或采用兽医给出的日期，不自动推断具体接种时间。

## 2. 调研结论与产品约束

### 2.1 指南显示接种间隔因疫苗和猫咪情况而异

- WSAVA 2024 指南建议，幼猫核心猫三联通常从至少 6 周龄开始，每 3–4 周接种一次，直到至少 16 周龄；高风险情况下可延续至 20 周龄。成年猫初次接种或接种史不完整时，通常也需要考虑间隔 2–4 周的两剂初免。
- FeLV 疫苗初免通常为两剂，间隔 3–4 周；后续加强安排还需结合接种史、暴露风险及产品说明。
- 狂犬疫苗的接种年龄和加强间隔应优先遵循当地规定；没有适用规定时遵循产品说明。不同产品的免疫持续期可能不同。

因此，“约一个月后提醒”可作为部分初免系列的候选提醒时间，不能作为所有疫苗的默认接种规则。规则和建议必须展示适用条件与来源。

参考：[WSAVA 2024 犬猫疫苗接种指南](https://wsava.org/wp-content/uploads/2024/04/WSAVA-Vaccination-guidelines-2024.pdf)、[AAHA/AAFP 猫核心疫苗接种建议](https://www.aaha.org/resources/2020-aahaaafp-feline-vaccination-guidelines/core-vaccines-for-pet-cats/)。

### 2.2 AI 的职责边界

接种时间由后端维护的规则集或兽医提供的日期决定。AI 可以解释建议、指出缺少的信息并帮助用户核对，但不能脱离规则自行编造日期，也不能在用户确认前创建正式提醒。

若规则集没有覆盖某种疫苗、产品或接种情形，界面应改为“请按兽医建议或产品说明设置日期”，允许用户手动选日期。

## 4. 用户流程

### 4.1 记录接种

从快速记录选择“疫苗”后，打开疫苗专属表单：

| 字段 | 要求 | 说明 |
|---|---|---|
| 猫咪 | 必填 | 绑定当前猫咪，提交时由后端校验家庭归属 |
| 接种日期 | 必填 | 默认本地当前日期，可修改 |
| 疫苗类型/名称 | 必填 | 猫三联、FeLV、狂犬、其他、不确定 |
| 针次/阶段 | 必填或可选“不确定” | 首针、后续针、加强针、未知 |
| 猫咪年龄/出生日期 | 读取档案；不完整时提示补充 | 幼猫系列规则可能依赖周龄 |
| 品牌/产品 | 可选 | 供产品说明和加强间隔核对 |
| 诊所、批号、备注 | 可选 | 用于追溯接种信息 |
| 添加下一次待办 | 条件显示 | 有适用规则时默认提供；用户可关闭 |

### 4.2 展示接种建议

保存疫苗记录后，系统展示建议卡片：

- 疫苗类型、当前针次和用于判断的年龄/接种史。
- 建议日期范围、默认提醒日期及生成原因。
- 规则名称、版本和来源链接。
- “调整日期”“创建待办”“暂不提醒”三个动作。
- 医疗提示：“建议用于预约或核对时间，实际接种安排以兽医意见和产品说明为准。”

以适用的幼猫猫三联初免为例，可说明常见间隔为 3–4 周，并给出日期窗口；默认提醒日建议落在可选窗口内，例如接种后第 28 天，用户可以修改。待办标题使用“联系诊所确认/预约下一针”，避免把提醒日表达成强制接种日。

如果接种信息不足、猫龄未知或规则无法匹配，展示手动日期选择器，不显示确定性的 AI 日期建议。

### 4.3 提醒与下一针闭环

- 用户确认后，创建关联猫咪的疫苗待办，在提醒中心显示计划日期、疫苗类型和针次。
- 用户可从待办进入对应猫咪的疫苗记录页，完成接种后将本条待办标记完成，并生成下一轮建议。
- 若用户直接新建了同类疫苗记录，提供关联已有待办的确认入口，避免重复提醒。
- 待办应分为即将到期、今天到期、已逾期和已完成；“已逾期”仅表示计划日期已过，不代表猫咪漏种。

### 4.4 记录页日历浏览

**目标**：让用户按日期快速回看猫咪的健康与生活记录；日历是记录浏览入口，不改变现有记录类型和记录详情。

**页面结构与默认行为**
- 保留页面现有的快捷记录和 AI 记录入口；在记录浏览区增加「日历 / 列表」切换，首次进入默认「日历」，用户切到列表后记住本次页面会话中的选择。列表继续使用当前按日期分组的记录样式。
- 日历顶部展示当前月份、上月/下月按钮和「今天」按钮；周一至周日排列，日期格仅展示当前月日期。当前日期、选中日期和有记录日期分别使用清晰且互不冲突的样式。
- 日期格有记录时显示类型标记和记录总数；同一天多种类型最多显示 3 个标记，更多类型用「+N」表示。疫苗标记需能与其他健康记录区分；颜色之外还要有图标或辅助文字，不能只靠颜色传达含义。日期格的辅助朗读文本包含日期、记录数量和类型。
- 默认选中今天；切换月份后选中目标月份最近一条有记录的日期，没有记录时选中 1 日。选中日期后在月历下方展示当天记录，按本地发生时间升序排列。记录项显示时间、类型、摘要；「全部猫咪」模式下同时显示猫咪名称。点击记录进入现有记录详情。
- 提供单一的记录类型筛选器，默认「全部记录」，选项来自当前已有记录类型，并提供醒目的「疫苗」筛选；沿用页面现有猫咪切换器，不另造一套猫咪筛选状态。
- 在选中日期的明细区提供「记录这一天」入口，进入现有快速记录类型选择；所选日期以 `date=YYYY-MM-DD` 传递，目标表单将其作为本地日期默认值，用户仍可编辑。

**状态与反馈**
- 月历初次加载显示格子骨架；加载失败显示重试入口；切换月份时保留已有页面结构，避免整页闪白。
- 当月无记录时显示空状态和「记一条记录」入口；所选日期无记录时显示该日空状态及记录入口；筛选后无匹配记录时明确提示「此日期没有符合条件的记录」，可一键清除筛选。
- 月份翻页、日期选择、类型筛选和猫咪切换均应更新日期标记与当日明细；新增、编辑或删除记录后刷新受影响月份的数据。

**日期口径**
- 日历按家庭时区显示日期。普通记录以 `occurred_at` 转换到家庭时区后的日期归档；疫苗记录优先使用 `payload.vaccination_date`，避免接种日期因 UTC 转换跨日。
- 查询月份使用本地月初至月末的日期范围；不得通过 `toISOString().slice(0, 10)` 推导本地日期。列表详情中的时间展示继续沿用现有本地时区规则。

## 5. 接种规则与推荐策略

### 5.1 规则输入

规则判断至少使用：

- 疫苗类型/抗原和产品（若已知）。
- 接种日期、针次、既往接种记录和系列状态。
- 猫咪周龄或出生日期；生活风险信息仅在规则确实需要时使用。
- 用户或兽医录入的下一次日期。
- 用户家庭时区或设备本地时区。

### 5.2 首版规则范围

1. **幼猫猫三联初免**：已确认疫苗类型、针次和年龄信息时，按指南提供 3–4 周建议窗口；持续接种到达适用周龄后，再按规则提示后续复核/加强安排。
2. **成年猫初免或接种史不完整的猫三联**：根据疫苗类型和产品说明提示常见的 2–4 周后续剂量窗口；信息不完整时请求用户确认。
3. **FeLV**：可提供 3–4 周后的第二剂候选窗口；后续加强日期需结合初免完成日期、产品说明和风险信息。
4. **狂犬**：不套用通用的“一个月后”规则；要求用户依据当地规定、产品说明或兽医意见设置下一次日期。
5. **其他/不确定疫苗**：允许手动设置日期，并记录日期来源为“用户/兽医提供”。

规则表应包含：疫苗代码、适用阶段、针次条件、间隔最小/最大天数、年龄边界、地区/产品限制、指南来源、规则版本、生效时间和停用状态。规则版本需随建议和提醒保存，便于解释和审计。

### 5.3 时间处理

- 前端日期由用户本地日历选择；提交计划时间时携带时区，例如 `Asia/Shanghai`。
- 后端保存标准化时间，同时保留原时区用于本地展示。
- 以日期为主的待办可统一设置默认提醒时刻（例如上午 09:00），并允许调整。
- 不使用 `toISOString().slice(0, 16)` 作为本地默认时间或展示值，避免 UTC 转换产生时差。

## 6. 数据与接口设计

### 6.1 疫苗记录

短期可沿用现有 `daily_records` 主记录，并将专属字段放入结构化 payload，保证与时间线兼容。建议字段：

```json
{
  "vaccine_code": "fvrhcp",
  "vaccine_name": "猫三联",
  "product_name": "可选产品名",
  "dose_number": 1,
  "series_id": "可选接种系列标识",
  "manufacturer": "可选",
  "lot_number": "可选",
  "clinic": "可选",
  "age_weeks": 12,
  "next_due_date": null,
  "next_due_source": null
}
```

如果后续需要疫苗系列查询、批量统计、编辑和审计，新增 `vaccine_details` 或 `vaccine_series` 关系表，将接种明细与 `daily_records.id` 关联；避免长期依赖不可查询的自由文本。

### 6.2 建议与提醒

建议新增后端“下一针计划建议”能力，输入已保存的疫苗记录 ID，后端读取授权范围内的猫咪、记录和规则，返回：

```json
{
  "status": "suggested | needs_input | unsupported",
  "date_window_start": "YYYY-MM-DD",
  "date_window_end": "YYYY-MM-DD",
  "default_reminder_date": "YYYY-MM-DD",
  "title": "联系诊所确认猫三联第 2 针",
  "reason": "适用条件及间隔依据",
  "rule_id": "vaccine_rule_id",
  "rule_version": "1",
  "source_url": "指南或产品说明链接"
}
```

正式提醒复用现有 `POST /families/{familyId}/reminders`，继续使用 `type=vaccine`、`catId`、`scheduled_at` 和 `timezone`。建议扩展提醒元数据，至少关联 `source_record_id`、建议窗口、规则 ID/版本及原因；如果无法扩展提醒表，可先通过明确的扩展 JSON 字段承载，避免将机器可读数据塞进展示文案。

建议接口和创建提醒接口均需：

- 校验用户对家庭及猫咪的访问权限。
- 校验接种记录属于请求猫咪和家庭。
- 对“根据同一接种记录创建相同待办”实现幂等，防止重复点击生成多条。
- 对 AI/规则不可用的情况降级为手动日期选择，不影响接种记录保存。

### 6.3 小程序改造

- 在快速记录中增加 `vaccine` 专属字段配置和表单组件。
- 新增本地日期选择、针次选择、疫苗类型选择和建议卡片。
- 在 service 层增加建议查询和提醒创建方法。
- 在 `toReminder` 中保留 `scheduled_at`、`timezone` 和来源记录信息。
- 提醒中心、今日页根据计划日期分组排序，并显示疫苗名称、猫咪和状态。
- 支持通过疫苗待办打开对应猫咪的疫苗记录；成功入库后关联并完成待办。
- 日期展示与提交统一遵循本地时区规则，并覆盖跨日边界场景。

### 6.4 记录页日历查询
- 复用现有家庭记录列表接口的日期范围、猫咪和类型筛选，不新增日历专用表或接口；小程序 service 查询方法扩展为可传 `from`、`to`、`cat_id`、`type` 和分页参数。
- 每次加载当前月完整记录集合，按本地日期在前端聚合为 `YYYY-MM-DD -> records[]`，再生成日期格标记和选中日明细。需处理分页，不能因为默认单页条数限制漏掉月份后半段的记录标记。
- 「全部猫咪」时省略 `cat_id` 并展示家庭内记录；单猫模式继续传当前猫咪 ID。缓存键至少包含家庭、猫咪筛选、月份和类型筛选；记录增删改后使相关缓存失效。
- 疫苗归档日使用 `payload.vaccination_date`；其他记录使用家庭时区下的 `occurred_at`。日期筛选和聚合必须采用相同口径，确保边界日不会在月历和列表之间错位。
- 查询结果为空、接口失败和部分分页失败需要区分处理；部分结果不可呈现为「没有记录」，应提示加载失败并允许重试。

## 7. AI 安全与失败处理

- 后端规则服务是计划日期和允许窗口的唯一来源；LLM 不直接拥有任意创建疫苗计划的能力。
- AI 只基于规则返回值生成面向用户的说明；模型输出日期必须由后端校验在建议窗口和适用规则内。
- 用户确认之前，提醒保持为建议态，不进入正式提醒列表。
- 保存接种记录成功但建议服务失败时，保留记录并提示用户手动设置日期。
- 规则不适用、信息矛盾、日期已过或猫咪档案缺少必要年龄信息时，返回 `needs_input`，明确要求补充。
- 医疗说明始终标注参考来源和“最终安排请遵医嘱/产品说明”。

## 8. 实施阶段

### 阶段一：可用闭环（MVP）

- 完成疫苗专属记录表单和结构化数据保存。
- 实现有限、版本化的核心规则：幼猫猫三联初免、FeLV 初免；狂犬和未知类型使用手动日期。
- 保存后展示建议窗口，支持编辑日期并由用户确认创建待办。
- 接通提醒创建服务，映射并展示 `scheduled_at` 和时区。
- 提醒中心可查看、完成和按到期状态分组；提供从待办进入记录的入口。
- 增加规则计算、家庭隔离、重复创建、失败降级和时区相关自动化测试。

- 记录浏览区增加日历/列表切换，默认日历；支持月份导航、今天快捷返回、按猫咪和记录类型筛选、当天明细及跳转详情。
- 支持从选中日期创建记录，并将该日期预填到快速记录表单；保留用户修改日期的能力。
### 阶段二：接种系列与通知

- 增加接种系列管理和记录关联，自动识别下一针次及系列完成状态。
- 增加产品说明数据、地区规则配置、规则更新和审计管理。
- 支持小程序订阅消息等外部通知渠道；必须在用户主动授权后发送，并保留应用内待办作为基础能力。
- 在猫咪健康档案中提供接种历史、后续计划和记录导出。

## 9. 验收标准

1. 从“快速记录 → 疫苗”可填写疫苗类型、接种日期和针次，且记录能在对应猫咪的健康记录中查看。
2. 符合规则的幼猫猫三联初免记录会显示 3–4 周建议窗口、明确原因和来源；默认提醒日期可编辑。
3. FeLV、狂犬、未知疫苗不会错误套用猫三联的默认间隔；缺信息时能提示补充或手动选择日期。
4. 用户确认后，提醒中心显示正确猫咪、疫苗名称、本地日期和待办状态；重复点击不会生成重复提醒。
5. 从提醒进入记录并保存后，可以完成关联待办；下一针建议根据新记录重新计算。
6. 后端拒绝跨家庭或错误猫咪的记录/提醒关联；AI 服务故障不影响疫苗记录保存。
7. 日期显示、提交和服务端保存经过时区验证，设备本地提醒日期不出现固定 8 小时偏移或跨日错误。
8. 所有日期建议可追溯至规则 ID、规则版本及来源；用户可调整或取消待办。

9. 记录页首次进入日历视图时默认选中今天；上月、下月和「今天」导航结果正确，月首/月末不产生日期错位。
10. 有记录的日期显示类型标记；同日多条记录不会重复堆叠标记，超过展示上限时显示更多数量；疫苗标记可被识别。
11. 选择日期后只展示该日匹配的记录，按家庭本地时间排序；点击记录可打开对应详情；「全部猫咪」模式下显示每条记录所属猫咪。
12. 猫咪切换、类型筛选和月份切换会同步更新日期标记和当天明细；清除筛选后恢复完整结果。
13. 空月份、空日期、筛选无结果、加载失败和分页失败均有不同且可操作的反馈；不得将接口失败显示成空记录。
14. 选择历史日期创建记录时，快速记录表单默认日期与所选日期一致；疫苗记录始终按 `vaccination_date` 落在正确日期，普通记录按家庭时区归档。
15. 新增、编辑或删除记录后，日历标记、当天数量和明细及时更新；分页后完整月份的记录均可见。
## 10. 主要风险与处理

| 风险 | 处理方式 |
|---|---|
| 用户只选了“疫苗”，未提供疫苗种类或针次 | 返回需要补充信息；允许手动建立待办 |
| 地区、产品说明和指南存在差异 | 规则版本化，并保留产品/地区覆盖能力；狂犬默认要求核对当地规定和产品说明 |
| LLM 给出不受规则支持的日期 | 日期只由服务端规则确定，LLM 只解释，后端校验输出 |
| 同一记录产生多条提醒 | 使用 `source_record_id` 和幂等键约束 |
| 用户实际接种后旧待办未完成 | 通过待办入口记录接种并关联完成；支持用户确认已有记录与待办的匹配 |
| 小程序日期和后端 UTC 不一致 | 请求携带 IANA 时区，展示时按对应时区格式化；不把 UTC 字符串截断后当本地时间 |

| 日历日期与 UTC 时间转换不一致，记录落到前后一天 | 普通记录统一转家庭时区；疫苗使用 `vaccination_date`；月历、筛选、明细共用同一日期口径 |
| 单页记录上限导致月历漏标 | 按月份完成分页后再生成标记；分页不完整时显示错误状态，不伪装成无记录 |
| 新增/编辑/删除后显示旧缓存 | 对受影响的猫咪和月份执行缓存失效或局部重算 |
| 全部猫咪视图下记录归属不清 | 当日明细逐条展示猫咪名称，并保持记录详情跳转到原记录 |
